FinShield AI — Team Task Poll (8 independent options)
How to use: paste this into your group chat and ask everyone to vote ONE option (A–H).
Rule: one option per person. Each option is an end-to-end slice (Backend + Frontend + Tests).

A) Transactions — List + Detail (end-to-end)
- Backend:
  - Implement GET /api/v1/transactions (pagination + filters: status, risk_level, amount range, date range)
  - Implement GET /api/v1/transactions/{id}
  - Add integration tests for list + detail
- Frontend:
  - Build Transactions page: table + filters + pagination
  - Build Transaction detail page: key fields + linked sections placeholders
  - Add at least 1 unit test for filters/table rendering
. 
B) Fraud Alerts — List + Detail + Status update (end-to-end)
- Backend:
  - Implement GET /api/v1/fraud-alerts (pagination + filters: status, severity, type, date)
  - Implement GET /api/v1/fraud-alerts/{id}
  - Implement PUT /api/v1/fraud-alerts/{id}/status (validate allowed transitions)
  - Add integration tests for list + status update
- Frontend:
  - Build Alerts list page (filters + table)
  - Build Alert detail page (status change UI)
  - Add a simple e2e smoke test for opening alert detail

C) Rules Engine — Rule CRUD + Toggle + Test rule (end-to-end)
- Backend:
  - Implement rules CRUD (GET/POST/PUT/DELETE) and PUT /api/v1/rules/{id}/toggle
  - Implement POST /api/v1/rules/{id}/test (dry-run against sample transaction)
  - Add unit tests for rule condition evaluation + integration test for CRUD
- Frontend:
  - Build Rules list page
  - Build Create Rule page (simple form first; visual builder can be minimal/stubbed)
  - Build Rule test panel UI to submit a sample transaction and view results

D) Auth basics — Login + Current user profile (end-to-end)
- Backend:
  - Implement POST /api/v1/auth/login
  - Implement GET /api/v1/auth/me (JWT required)
  - Add unit tests for auth service + integration test for login->me flow
- Frontend:
  - Build Login page connected to backend
  - Add “current user” fetch on dashboard shell and show user name/email
  - Add basic form validation (zod/react-hook-form)

E) Risk Scoring — Entity risk profile + history (end-to-end)
- Backend:
  - Implement GET /api/v1/risk-scoring/entity/{entity_id}
  - Implement GET /api/v1/risk-scoring/entity/{entity_id}/history
  - Add unit tests for risk score calculation/formatting (even if mocked data at first)
- Frontend:
  - Build Risk scoring page (profile view + small history chart placeholder)
  - Add types + hooks for risk endpoints

F) Analytics — Overview metrics + Fraud trends (end-to-end)
- Backend:
  - Implement GET /api/v1/analytics/overview
  - Implement GET /api/v1/analytics/fraud-trends
  - Add integration tests (returns shape + basic query params)
- Frontend:
  - Build Analytics overview page (cards)
  - Add a trends chart component wired to the trends endpoint

G) Entities — Entity list + Entity 360 view (end-to-end)
- Backend:
  - Implement GET /api/v1/entities (pagination + filters: entity_type, risk_level, kyc_status)
  - Implement GET /api/v1/entities/{id}
  - Add integration tests for list + detail
- Frontend:
  - Build Entities list page (table + filters)
  - Build Entity detail page (basic sections: profile, risk, recent activity placeholders)

H) Watchlists — List + Add entry + Screen endpoint (end-to-end)
- Backend:
  - Implement GET /api/v1/watchlists
  - Implement POST /api/v1/watchlists
  - Implement POST /api/v1/watchlists/screen (screen a provided entity payload)
  - Add unit test for matching logic (can be simple deterministic scoring first)
- Frontend:
  - Build Watchlists page (list + add form)
  - Build Screen form UI (paste entity details -> show matches)

Notes for everyone
- Keep changes inside your feature area to avoid merge conflicts.
- Add/adjust tests for critical behavior in your slice.
- Don’t include secrets in commits; only update example env files if needed.
